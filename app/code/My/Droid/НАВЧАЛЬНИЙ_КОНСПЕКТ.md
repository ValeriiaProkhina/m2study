## 🔧 Детальний розбір кожного файлу

### 1. `registration.php` (ОБОВ'ЯЗКОВИЙ)
**Призначення**: Реєструє модуль у Magento  
**Залежності**: `Magento\Framework\Component\ComponentRegistrar`

```php
<?php
\Magento\Framework\Component\ComponentRegistrar::register(
    \Magento\Framework\Component\ComponentRegistrar::MODULE,
    'My_Droid',     // Namespace_ModuleName
    __DIR__          // Шлях до папки модуля
);
```

**Ключові моменти**:
- Має бути в корені модуля
- Ім'я модуля: `Vendor_Module` (CamelCase)
- Без нього модуль НЕ буде виявлений Magento

---

### 2. `etc/module.xml` (ОБОВ'ЯЗКОВИЙ)
**Призначення**: Декларує модуль і його версію  
**Залежності**: Немає прямих залежностей

```xml
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
        xsi:noNamespaceSchemaLocation="urn:magento:framework:Module/etc/module.xsd">
    <module name="My_Droid" setup_version="1.0.0" />
</config>
```

**Ключові моменти**:
- `name` - має співпадати з назвою з registration.php
- `setup_version` - версія модуля (застаріле у M2.3+, але все ще використовується)
- Можна додати `<sequence>` для залежностей від інших модулів

---

### 3. `etc/config.xml`
**Призначення**: Значення за замовчуванням для System Configuration  
**Залежності**: Має співпадати зі structure у `system.xml`

```xml
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
        xsi:noNamespaceSchemaLocation="urn:magento:module:Magento_Store:etc/config.xsd">
    <default>
        <!-- Шлях: section_id/group_id/field_id -->
        <my_droid_promo>
            <general>
                <background_color>#f0c14b</background_color>
                <text_color>#111111</text_color>
            </general>
        </my_droid_promo>
    </default>
</config>
```

**Ключові моменти**:
- Структура `<default>` -> `<section>` -> `<group>` -> `<field>`
- ID мають співпадати з system.xml
- Значення стають default у БД (таблиця `core_config_data`)

### 4. `etc/adminhtml/system.xml` (System Configuration)
**Призначення**: Створює налаштування в адмінці  
**Шлях в адмінці**: Stores → Configuration → [Your Tab]

```xml
<?xml version="1.0"?>
<config xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
        xsi:noNamespaceSchemaLocation="urn:magento:module:Magento_Config:etc/system_file.xsd">
    <system>
        <!-- TAB: Вкладка в меню конфігурації -->
        <tab id="my_droid" translate="label" sortOrder="200">
            <label>My Droid</label>
        </tab>

        <!-- SECTION: Група налаштувань -->
        <section id="my_droid_promo" translate="label" type="text" 
                 sortOrder="10" showInDefault="1" showInWebsite="1" showInStore="1">
            <label>Promo Bar Settings</label>
            <tab>my_droid</tab>
            <resource>My_Droid::config</resource>  <!-- ACL resource -->

            <!-- GROUP: Підгрупа -->
            <group id="general" translate="label" type="text" 
                   sortOrder="10" showInDefault="1" showInWebsite="1" showInStore="1">
                <label>General Settings</label>

                <!-- FIELD: Конкретне поле -->
                <field id="background_color" translate="label comment" type="text" 
                       sortOrder="10" showInDefault="1" showInWebsite="1" showInStore="1">
                    <label>Background Color</label>
                    <comment>Choose the background color for the promo bar</comment>
                    <validate>color</validate>  <!-- HTML5 валідація -->
                </field>

                <field id="text_color" translate="label comment" type="text" 
                       sortOrder="20" showInDefault="1" showInWebsite="1" showInStore="1">
                    <label>Text Color</label>
                    <comment>Choose the text color for the promo bar</comment>
                </field>
            </group>
        </section>
    </system>
</config>
```

**Ключові атрибути**:
- `showInDefault/showInWebsite/showInStore` - на яких рівнях доступне
- `sortOrder` - порядок відображення
- `translate` - які атрибути перекладаються
- `type` - тип поля (text, select, multiselect, textarea, etc.)
- `validate` - валідація (color, email, url, etc.)

**Додаткові можливості**:
```xml
<!-- Frontend Model (власний блок) -->
<frontend_model>Vendor\Module\Block\Adminhtml\System\Config\Color</frontend_model>

<!-- Backend Model (обробка перед збереженням) -->
<backend_model>Magento\Config\Model\Config\Backend\Encrypted</backend_model>

<!-- Source Model (список опцій для select) -->
<source_model>Magento\Config\Model\Config\Source\Yesno</source_model>

<!-- Config Path (альтернативний шлях зберігання) -->
<config_path>design/header/logo_src</config_path>

<!-- Depends (показувати тільки якщо інше поле має певне значення) -->
<depends>
    <field id="enabled">1</field>
</depends>
```

### 5. `Helper/Config.php`
**Призначення**: Отримання значень з System Configuration  
**Залежності**: `Magento\Framework\App\Helper\AbstractHelper`

```php
<?php
declare(strict_types=1);

namespace My\Droid\Helper;

use Magento\Framework\App\Helper\AbstractHelper;
use Magento\Store\Model\ScopeInterface;

class Config extends AbstractHelper
{
    // XML шляхи (section/group/field)
    const XML_PATH_BACKGROUND_COLOR = 'my_droid_promo/general/background_color';
    const XML_PATH_TEXT_COLOR = 'my_droid_promo/general/text_color';

    /**
     * Отримати значення конфігурації
     * 
     * @param int|null $storeId - ID магазину
     * @return string
     */
    public function getBackgroundColor($storeId = null): string
    {
        return (string) $this->scopeConfig->getValue(
            self::XML_PATH_BACKGROUND_COLOR,
            ScopeInterface::SCOPE_STORE,  // Рівень: default/website/store
            $storeId
        );
    }

    public function getTextColor($storeId = null): string
    {
        return (string) $this->scopeConfig->getValue(
            self::XML_PATH_TEXT_COLOR,
            ScopeInterface::SCOPE_STORE,
            $storeId
        );
    }
}
```

**Scope рівні**:
- `ScopeInterface::SCOPE_STORE` - Store View
- `ScopeInterface::SCOPE_WEBSITE` - Website
- `ScopeConfigInterface::SCOPE_TYPE_DEFAULT` - Global (Default)

### 6. `Block/PromoBar.php`
**Призначення**: Передає дані з PHP в PHTML/JS  
**Залежності**: `Magento\Framework\View\Element\Template`, власний Helper

```php
<?php
declare(strict_types=1);

namespace My\Droid\Block;

use Magento\Framework\View\Element\Template;
use My\Droid\Helper\Config;

class PromoBar extends Template
{
    private $configHelper;

    public function __construct(
        Template\Context $context,
        Config $configHelper,
        array $data = []
    ) {
        $this->configHelper = $configHelper;
        parent::__construct($context, $data);
    }

    public function getBackgroundColor(): string
    {
        return $this->configHelper->getBackgroundColor();
    }

    public function getTextColor(): string
    {
        return $this->configHelper->getTextColor();
    }
}
```

**Ключові моменти**:
- Dependency Injection через `__construct`
- Публічні методи доступні в PHTML: `$block->getBackgroundColor()`
- Context містить всі базові залежності (request, scopeConfig, eventManager, etc.)

### 7. `view/frontend/layout/default.xml`
**Призначення**: Додає блок на всі сторінки frontend  
**Залежності**: Структура Layout XML

```xml
<?xml version="1.0"?>
<page xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
      xsi:noNamespaceSchemaLocation="urn:magento:framework:View/Layout/etc/page_configuration.xsd">
    <body>
        <!-- Додаємо в існуючий контейнер -->
        <referenceContainer name="header.container">
            <block class="My\Droid\Block\PromoBar" 
                   name="promo.bar" 
                   template="My_Droid::promo-bar.phtml" 
                   after="-">
                
                <!-- jsLayout для UI Components -->
                <arguments>
                    <argument name="jsLayout" xsi:type="array">
                        <item name="components" xsi:type="array">
                            <item name="promo-bar-component" xsi:type="array">
                                <item name="component" xsi:type="string">My_Droid/js/view/promo-bar</item>
                                <item name="config" xsi:type="array">
                                    <item name="freeShippingThreshold" xsi:type="number">100</item>
                                    
                                    <!-- Виклик методів Block -->
                                    <item name="backgroundColor" xsi:type="helper" 
                                          helper="My\Droid\Block\PromoBar::getBackgroundColor" />
                                    <item name="textColor" xsi:type="helper" 
                                          helper="My\Droid\Block\PromoBar::getTextColor" />
                                </item>
                            </item>
                        </item>
                    </argument>
                </arguments>
            </block>
        </referenceContainer>
    </body>
</page>
```

**Ключові елементи**:
- `<referenceContainer>` - звертається до існуючого контейнера
- `<block>` - створює новий блок
- `class` - PHP клас блоку
- `template` - PHTML шаблон
- `after="-"` - позиція (після всіх інших блоків)
- `xsi:type="helper"` - викликає метод блоку

**Інші типи аргументів**:
```xml
<item name="text" xsi:type="string">Hello</item>
<item name="number" xsi:type="number">42</item>
<item name="bool" xsi:type="boolean">true</item>
<item name="array" xsi:type="array">...</item>
<item name="object" xsi:type="object">Vendor\Module\Model\Class</item>
```

### 8. `view/frontend/templates/promo-bar.phtml`
**Призначення**: HTML template з Knockout.js bindings  
**Залежності**: Knockout.js, Magento_Ui/js/core/app

```php
<!-- Scope для Knockout компонента -->
```

**Ключові моменти**:

- `$block->getJsLayout()` - виводить jsLayout з layout XML

### 9. `view/frontend/web/js/view/promo-bar.js` (Knockout.js)
**Призначення**: Логіка UI компонента  
**Залежності**: uiComponent, knockout, customerData

```javascript
define([
    "uiComponent",
    "Magento_Customer/js/customer-data",
    "ko",
    "Magento_Catalog/js/price-utils",
], function (Component, customerData, ko, priceUtils) {
    "use strict";

    return Component.extend({
        // Значення за замовчуванням (перезаписуються з jsLayout)
        defaults: {
            template: "My_Droid/promo-bar",
            freeShippingThreshold: 100,
            backgroundColor: "#f0c14b",
            textColor: "#111111",
        },

        // Ініціалізація компонента
        initialize: function () {
            this._super();  // Викликає батьківський initialize
            
            // Отримуємо дані кошика (реактивні)
            this.cart = customerData.get("cart");

            // Computed Observable - автоматично оновлюється
            this.cartSubtotal = ko.computed(function () {
                const cartData = this.cart();
                return cartData && cartData.subtotalAmount
                    ? parseFloat(cartData.subtotalAmount)
                    : 0;
            }, this);

            this.amountLeft = ko.computed(function () {
                const left = this.freeShippingThreshold - this.cartSubtotal();
                return left > 0 ? left : 0;
            }, this);

            this.progressWidth = ko.pureComputed(function () {
                const progress = (this.cartSubtotal() / this.freeShippingThreshold) * 100;
                return (progress > 100 ? 100 : progress) + "%";
            }, this);
        },

        // Форматування ціни
        getFormattedAmountLeft: function (amount) {
            return priceUtils.formatPrice(
                amount,
                window.checkoutConfig ? window.checkoutConfig.format : {}
            );
        },
    });
});
```

**Ключові концепції Knockout.js**:
- `ko.observable()` - реактивна змінна (можна змінювати)
- `ko.computed()` - обчислювана змінна (залежить від інших)
- `ko.pureComputed()` - оптимізована computed (без side-effects)

### 10. `view/frontend/web/template/promo-bar.html` (KO Template)
**Призначення**: HTML template для Knockout  
**Залежності**: Knockout.js bindings

```html
<div class="promo-bar" data-bind="style: { 
    backgroundColor: backgroundColor, 
    color: textColor 
}">
    <div class="promo-bar__content">
        <!-- ko if: amountLeft() > 0 -->
        <p>
            Add <span data-bind="text: getFormattedAmountLeft(amountLeft())"></span> 
            more to get FREE shipping!
        </p>
        <!-- /ko -->
        
        <!-- ko if: amountLeft() === 0 -->
        <p>🎉 Congratulations! You've earned FREE shipping!</p>
        <!-- /ko -->
        
        <div class="promo-bar__progress">
            <div class="promo-bar__progress-bar" 
                 data-bind="style: { width: progressWidth() }">
            </div>
        </div>
    </div>
</div>
```

**Knockout bindings**:
- `data-bind="text: variable"` - текст
- `data-bind="html: variable"` - HTML
- `data-bind="visible: condition"` - показати/сховати
- `<!-- ko if: condition -->` - умовний рендеринг
- `data-bind="foreach: array"` - цикл
- `data-bind="style: { property: value }"` - inline стилі
- `data-bind="click: method"` - обробник кліку

## 🎯 Типи компонентів Magento 2 та їх створення

### 1. **System Configuration Field** (як у цьому прикладі)

**Схожі компоненти**:
- Будь-які налаштування в адмінці (Stores → Configuration)
- Всі system.xml поля створюються однаково

**Файли потрібні**:
```
etc/adminhtml/system.xml     ✅ ОБОВ'ЯЗКОВО
etc/config.xml               ⚠️ Опційно (default values)
Helper/Config.php            ⚠️ Опційно (для зручності читання)
Block/.../Color.php          ⚠️ Тільки для кастомних frontend_model
```

**Відмінності**:
- **Прості поля** (text, select, textarea) - тільки system.xml
- **Кастомні поля** (color picker, file upload) - потрібен frontend_model блок
- **Валідація** - через backend_model
- **Динамічні опції** - через source_model

### 2. **UI Component (Knockout.js)** - як Promo Bar

**Схожі компоненти**:
- Checkout компоненти

## ⚠️ Найчастіші ситуації та помилки

### 1. **Проблема**: `Class does not exist`
**Причина**: Неправильний namespace або автозавантаження  
**Рішення**:
```bash
php bin/magento setup:upgrade
php bin/magento cache:clean
rm -rf generated/code/*
```

### 2. **Проблема**: Налаштування не зберігаються
**Причина**: Немає ACL resource  
**Рішення**: Створити `etc/acl.xml`
```xml
<resource id="Magento_Backend::admin">
    <resource id="Magento_Backend::stores">
        <resource id="Magento_Backend::stores_settings">
            <resource id="Magento_Config::config">
                <resource id="Vendor_Module::config" title="My Settings" />
            </resource>
        </resource>
    </resource>
</resource>
```

### 3. **Проблема**: UI Component не працює
**Причина**: Неправильний jsLayout або шлях до JS  
**Рішення**:
- Перевірити `component` path: `Vendor_Module/js/view/component`
- Очистити RequireJS кеш: `pub/static/frontend/`

### 4. **Проблема**: Helper повертає null
**Причина**: Неправильний XML path  
**Рішення**: Шлях має бути `section_id/group_id/field_id`

### 5. **Проблема**: Block не відображається
**Причина**: Layout XML не застосувався  
**Рішення**:
```bash
php bin/magento cache:clean layout full_page
```

### 6. **Проблема**: Knockout не оновлює дані
**Причина**: Не використовується observable  
**Рішення**: Використати `ko.observable()` або `ko.computed()`
